Answers three questions from the owner. Ground truth: `docs/STATUS.md` (partly stale, last updated 2026-10-05), `docs/REVIEW_2026-10-06.md`, `docs/analysis/2026-10-06_ring_drift.md`, the package READMEs and `git log` through `4948faa`. Legend: **Done** = merged and exercised on hardware. **Done (bench)** = merged, tested off-robot only. **WIP** = in progress or partially done. **Todo** = not started. ## 2. Learning from every mow

Goal: every mow produces a small, self-describing record; a post-mow job turns it into a report and metrics; metrics accumulate per area; a bounded optimiser proposes settings; the owner approves; the next mows test them.

### 2.1 Capture (on the mower)

New package `src/mower_mowlog` (Python):

- `mowlog_recorder` node: starts a rosbag2 recording on mission state entering `UNDOCKING`/`MOWING` and stops on `IDLE_DOCKED`/`IDLE`/`EMERGENCY` + 30 s. Uses `rosbag2_py` with storage `mcap` and zstd chunk compression (MCAP is the Humble-supported plugin `ros-humble-rosbag2-storage-mcap`). Replaces the ad-hoc CSV recorder used for the drift analysis (it lived in `/tmp`, had a duration limit and missed both runs).
- Topic set (≈ low rate, no images by default):

| Topic | Rate | Why |
|---|---|---|
| `/odometry/filtered`, `/odometry/filtered_map` | 30 Hz | Track, cross-track, coverage replay |
| `/odom` (wheel) | 50 Hz | Slip = wheel vs EKF |
| `/imu/data`, `/imu/data_aligned` | 100 Hz (downsample 25) | Tilt, slope, yaw rate |
| `/fix`, `/fix_status` | 10 Hz | RTK quality vs errors |
| `/cmd_vel_nav`, `/cmd_vel`, `/mower_mcu_driver/sent_speed` | event | Commanded vs post-clamp vs achieved |
| `/mower_base/status`, `/battery`, `/mower_sensor_info` | 10 Hz | Blade state, current, battery, lift |
| `/behavior_tree_node/high_level_status`, mission sub-state | on change | Segmentation |
| `/plan` / coverage plan + `drivable_subpaths` (latched once) | once | Planned vs achieved |
| `/ai/det/*` detections, `/obstacle_policy` events, `/dig_stall`, boundary violations | event | Obstacle and stall events |
| `/rosout` (level >= WARN) | event | Context |
| `/tf_static`, `/tf` (map, odom, base_link only) | 30 Hz | Replay |

- Optional "event snapshots": on stall, obstacle stop, boundary violation or e-stop, save 10 s of JPEG from the relevant camera (ring buffer in RAM). ~1-3 MB per event.
- Size: the non-image set is roughly 0.5-1.5 MB/min compressed (estimate; measure on the first mow). A 90-minute mow ≈ 50-130 MB. Retention on `/userdata` (≈ 18-24 GB free of the 32 GB eMMC): quota 4 GB for bags, keep the last 20 mows full, then keep only the derived report + a 1 Hz decimated track forever (≈ 1 MB per mow). Enforce the quota in the recorder before starting. eMMC wear is not a concern at this rate.

### 2.2 Post-mow analysis (on the mower, after docking, low priority `nice 19`)

`mower_mowlog/analyze.py` (pure Python, numpy + shapely, unit-testable off-robot on recorded bags) writes `report.json` next to the bag:

- **Segmentation**: label each sample with segment type from the plan (ring, swath, turn type: loop / reverse-curve / pivot, transit, dock, undock, detour).
- **Tracking**: cross-track error (RMS, p95, max) and heading error per segment type; % time the angular command was saturated at the clamp; commanded vs achieved yaw rate (the ring_drift metric).
- **Turns**: success, duration, overshoot, number of retries per turn type.
- **Slip / stall**: wheel-vs-EKF speed ratio, `/dig_stall` events, positions.
- **Boundary**: excursions (count, max distance outside, position, segment type).
- **Coverage**: buffer the blade footprint (`cut_width`) along the EKF track while `is_cutting`, intersect with the area polygon minus obstacles; output achieved %, missed polygons (> 0.05 m²), double-cut %. This is the same code as the in-progress gap filling; put it in one library (`mower_coverage_bridge` or a new `mower_coverage_eval`) used by both.
- **Energy**: Wh per m² cut and per metre transit, blade current vs speed, battery at start/end.
- **Obstacles**: stops, detours, skipped stretches, class, duration; false-stop candidates (stop with no detection persisted > 1 s).
- **Localisation**: time in RTK fixed / float / none; heading-aligner quality over time.
- **Context**: start time, sun elevation, weather if known, settings snapshot (`mowgli_robot.yaml` + area settings hash + git SHA).

Rows also append to `/userdata/ros2/mowlog/history.sqlite` (one row per mow x area x metric).

### 2.3 Mow report in the GUI

- `mower_gui_bridge` serves `/mowlog/list` and `/mowlog/report` (Trigger-style services or a small HTTP endpoint the Go backend proxies).
- `StatisticsPage.tsx` (exists) gets: last-mow card (coverage %, duration, Wh/m², events), a map overlay (achieved footprint heatmap, missed polygons, excursions, stall pins), trends per area (coverage %, cross-track RMS, Wh/m²), and an "event clips" list. Upstreamable to MowgliNext behind the Tron profile gate.

### 2.4 Automatic parameter proposals (guard-railed)

`mower_mowlog/tuner.py`:

- **Parameters** (per area): lookahead / FTC gains, linear speed, `min_turn_radius_m`, turn type, edge margin / ring inset, swath overlap, mow angle.
- **Objective**: weighted score = coverage % - a·cross-track p95 - b·excursions - c·minutes per 100 m² - d·Wh/m², with hard constraints (zero excursions beyond 0.1 m, zero e-stops caused by tracking).
- **Search**: start with a coarse grid over 2 parameters at a time; once ≥ 8 mows per area exist, use bounded Bayesian optimisation (`scikit-optimize` or `optuna`, both pure Python) inside a trust region of ±15 % of the current value. Safety bounds are fixed in a reviewed yaml (`mowlog/bounds.yaml`): e.g. speed ≤ 0.3, ring inset ≥ 0.10 m, never touch safety parameters (gate, guard, battery, boundary).
- **A/B**: alternate settings sets per mow on the same area, or split one area in two halves with different settings when the polygon allows, so weather and grass state cancel out. Require ≥ 3 mows per arm before a proposal.
- **Approval**: proposals appear in the GUI as a diff with the evidence; nothing applies without the owner's tap. Applied changes are written to area settings with a revision record and one-tap rollback.

### 2.5 Where the LLM agent fits

- A `/mow-review` skill in `ros2_stack/.claude/skills/mow-review/SKILL.md`: pull the last report + bag over ssh (`deploy_to_mower.sh` paths), run `analyze.py` locally if needed, read `/rosout` WARN/ERROR around each event, compare to the previous 5 mows from `history.sqlite`, and write `docs/mows/<date>.md` with findings and a proposed diff (YAML parameter changes or code fixes) for the owner to review. It never deploys.
- Use it for things the numeric tuner cannot do: recognise a new failure pattern (like the independent-clamp bias found today), connect a log line to code, and propose a test. The ring_drift analysis today is the template.
- Optional later: Foxglove layouts checked into the repo for manual review of the same bags.

**Commercial features worth matching** (effort for this stack):

- Edge mode: one blade-off-to-boundary pass at a small inset with slow speed, per area (S-M). Our ring inset 0.20 m is the opposite trade-off.
- Multi-zone schedules with per-zone settings and a dusk/rain guard (S; GUI page exists).
- Anti-theft: lift-while-not-in-mission alarm (LEDs + MQTT notification), PIN to start, last GNSS position pushed on lift (S-M). The MCU lift flag already exists.
- Network RTK without a base (NTRIP): already supported in the GUI; needs a provider (S).
- Vision fallback when RTK floats: the long-term role of #11 (L).
- Mapping from imagery (drone/satellite): draw boundaries on an orthophoto in the GUI, then drive once to confirm (M). Useful but not core.
- Cut-height automation: blocked on the cutter height scale (S once verified).
